\section{Summary, Limitations, and Future Work}

\subsection{Summary}

This document describes a protocol-agnostic thermal-control core that has been implemented and exercised across a Linux host and the ESP32-C3, including a hardware-in-the-loop bring-up in which the host runs the control law over real bench peripherals. The v1 implementation plan --- Stages 0 through 16 --- is complete and CI-gated, including deterministic cross-platform replay parity and the figure-regeneration pipeline behind this draft's scenario plots. Post-v1 work has also shipped under the same gates: the CH32V003 \texttt{STANDALONE} port, the CH32 host-command bench path, and an advisory fan-health detector enabled on the telemetry image. The formal hardware benchmark sweep that will close the evidence trail is still pending. The result is not a production safety component, but a reproducible reference design with a measured-only evidence trail (Section~\ref{sec:evaluation}).

\subsection{Known Limitations}

\begin{itemize}[leftmargin=*]
    \item not ASIL-rated;
    \item no AUTOSAR integration in v1;
    \item OBD-II speed is a reproducible test source, not a production IVI integration strategy; a spoofed or stale speed signal can bias the acoustic reference policy, although CRITICAL and SHUTDOWN paths bypass the cap;
    \item runtime tuning is a development surface and should remain local, authenticated, or disabled in production deployments;
    \item the acoustic reference policy's PWM-seconds metric is only a proxy until calibrated SPL measurements exist;
    \item fan-health does not yet compensate its PWM-to-RPM baseline for intake temperature;
    \item CH32 UART telemetry can still drop records under sustained backpressure; the firmware now reports a cumulative drop counter, so captures must check it before being treated as complete evidence;
    \item v1 arbitration is max-wins only, with no strategy hook or actuator-load sharing;
    \item v1 governor dispatch is a closed two-value enum, not yet a pluggable governor interface;
    \item Linux scheduled-time ticking keeps the core deterministic and now reports overrun events, but fault windows still stretch in wall time if the process is stalled;
    \item RH850 is structurally planned but not hardware-validated in v1;
    \item the formal timing and acoustic benchmarks are not yet captured (Section~\ref{sec:eval-gaps}).
\end{itemize}

\subsection{Future Work}

\begin{itemize}[leftmargin=*]
    \item calibrated SPL measurement;
    \item controlled fan-degradation (dust-loading) measurement for the fan-health detector;
    \item temperature-compensated fan-health baselines;
    \item multi-input policy modifiers with explicit composition semantics;
    \item workload/power context and optional PID feed-forward;
    \item actuator linearization or an inner RPM loop for PID-controlled fans;
    \item a pluggable governor dispatch table before adding a third governor;
    \item backpressure mitigation for constrained UART telemetry paths;
    \item measured-time or skipped-period accounting modes for platforms that need wall-time-true fault windows;
    \item OEM CAN DBC integration outside the core;
    \item PID autotune;
    \item full RH850 validation;
    \item static-analysis and MISRA-oriented hardening.
\end{itemize}

\subsection{Draft Status}

The conceptual and implementation sections of this draft are written against the shipped code. The Evaluation section is preliminary: it now reports measured footprint, determinism, bring-up results, and the closed-loop scenario plots, and will grow to the full hardware benchmark sweep once that data is captured on instrumented hardware. Final quantitative claims and practical recommendations are written at that point.
